# 回合制与随机事件系统实施计划

## Context

现有 [game-state.ts](file:///workspace/src/game-state.ts) 已有按六点移动力逐格行军、攻城和回合计数，但非行军时 UI 不允许结束回合；`endTurn()` 有多个返回分支，尚无统一的回合结算、事件暂停和历史战报。用户已确认：首版采用随机事件与战报、事件由玩家选择、按纯回合数推进且允许空过；事件采用常规强度（每回合结算后30%概率，最多一个事件），无日期和AI。

## 推荐方案

保留纯状态转换架构，不引入通用事件总线或日期系统。每次有效结束回合先完成行军和战斗，增加回合号并记录战报，再以独立且可复现的32位伪随机状态抽取事件；新局使用固定默认seed，允许测试传入seed。若军队全灭，该回合仍保留战斗记录但不再抽事件。事件待选时阻止结束回合、派兵及其他战局操作；玩家选择后应用效果并解除暂停。事件和战斗记录合并保留最近50条，`lastBattle`继续供当前战报HUD使用。

首版事件内容固定为三类、等概率抽取：
- **流民来投**：接纳则军力增加500；婉拒则无效果。
- **山路泥泞**：绕行则下一次回合结算移动力减少2；强行整路则立即损失500军力，移动力不减。
- **乡导献策**：采纳则下一次回合结算移动力增加2；谢绝则无效果。

移动力修正仅作用于一次回合结算后清零；军力最低为0。事件日志记录发生回合、事件、选择与效果；战斗记录沿用现有战报字段。随机抽取完全由状态内seed推进，玩家界面不消耗随机数。

## 文件与职责

- 修改 `src/game-state.ts`：加入RNG状态、待选事件、一次性移动力修正和最多50条战报；统一所有结束回合分支经过结算尾部；添加选择事件的纯状态函数；pending事件时拒绝重复推进和派遣；待命、抵达时允许结束回合。
- 新增 `src/events.ts`：定义三类事件与选项、固定seed的32位伪随机抽取及事件选择效果纯函数；具名函数加简体中文函数级注释。
- 修改 `src/main.ts`、`src/style.css`：添加可访问的事件选择层及滚动战报列表；待选事件暂停并遮挡战局操作，选择后刷新军势、战报、城池和地图；同步回合按钮可用状态并显示当回合/新回合序号，不添加日期。
- 新增 `tests/events.test.ts`，扩展 `tests/game-state.test.ts`，修改 `package.json` 显式纳入事件测试。

## 实施任务

1. 先为事件抽取和选择写测试：同seed序列一致、30%边界、每回合至多一个、三类事件分布由固定样本验证、每种选项效果正确、随机状态只在抽取时推进。
2. 实现 `events.ts` 纯函数与事件/选项类型；运行 `npx tsx --test tests/events.test.ts`。
3. 为回合收尾、战斗先于事件、待命空过、待选暂停/一次选择、战败不再抽事件、一次性移动力修正、日志50条上限编写状态测试；兼容现有测试，显式处理测试中待选事件。
4. 扩展 `game-state.ts` 并通过纯状态测试；确保普通行军、占领、退兵和全灭等分支都只结算一次，不修改输入状态。
5. 实现 DOM 事件选择与日志 UI；按钮和状态显示由游戏状态驱动，避免仅依赖遮罩阻止操作。
6. 运行 `npm test`、`npm run build`、`git diff --check`；浏览器验证待命空过、行军结算后事件弹窗、事件选择效果与历史记录、待选期间不能推进/派遣，以及桌面与移动布局。

## 验收标准

- 相同seed与相同回合操作得到完全相同事件序列；30%触发、每回合至多一个。
- 行军/战斗先结算，再出现事件；待选期间无法推进或派遣，选择只生效一次。
- 任意有效回合可空过；移动力效果只生效一次；全灭不再生成新事件；日志最多50条。
- 所有测试、类型检查、生产构建通过，浏览器中事件交互和回合按钮状态正确。
