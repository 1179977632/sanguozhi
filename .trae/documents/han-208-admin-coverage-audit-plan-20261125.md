# 建安十三年州郡覆盖审计计划

> **执行要求：** 本计划获确认后开展资料核查并生成审计结果；本轮不扩充城池、不修改地图代码，不提交或部署。

**目标：** 以建安十三年（208）刘表病逝前为截面，建立独立于现有40城的行政单位核查名录，识别地图已代表、明确缺少和仍待考证的州郡单位，并给出有来源的补城候选清单。

**方法：** 先建立史料名录及沿革证据，再与现有城池双向比对。行政建置、城邑代表关系、实际控制和地图显示范围分别判断；证据不足即保留不确定性。

**工具：** 现有TypeScript数据只读提取、公开史料与历史地名数据库查询、Markdown审计说明、UTF-8 CSV台账。不增加项目依赖。

## 二、范围与判断口径

### 时间及层级

- 固定为208年刘表病逝前；不倒灌刘琮降曹后或208年后续变化。
- 核查州/司隶级单位，以及郡、国、尹等郡国级单位。县仅作为代表城邑和定位线索，不扩展成全国县级名录。
- 来源只记“208年设置”而无事件先后时，列为时间待核，不提前纳入已确认分母。
- 不限定于地图现有14个标签。边疆特殊建置、属国及归属有争议的单位单列解释，不强行并入普通郡级统计。
- 《后汉书·郡国志》是具有自身统计年代的基础名录，必须结合其后至截面的建置变化，不能直接称为208年完整名单。

### 地图覆盖与证据状态

每个单位分别记录以下字段，避免混用：

1. **截面有效性：** 确认有效、时间待核、确认不适用。
2. **地图关系：** 已覆盖、明确缺项、待核实、地图外、有意省略。
3. **证据状态：** 已交叉核实、多数支持、存在争议、单一来源。

具体规则：

- **已覆盖：** 单位在截面有效，且现有至少一座城的代表关系、当时归属得到核验；只表示有代表点，不表示完整绘制辖境。
- **明确缺项：** 单位在截面有效、代表地域可确定在地图显示范围内，现有城池没有对应记录，也无明确设计省略依据。
- **待核实：** 建置日期、归属、同名识别、代表城邑或地图内外关系证据不足/冲突。
- **地图外：** 有位置依据表明代表地域超出当前地图显示范围；局部相交但无法判断时仍列待核实，不根据示意轮廓推断完整辖境。
- **有意省略：** 仅用于存在明确设计依据的省略；不能把“没有画”自动解释为有意省略。
- 确认不适用的后置、已撤销等候选仍保留排除理由，但不纳入截面有效单位计数。
- 行政归属与实际控制分开；不同地域的同名单位不合并。同一单位的异名、改名、繁简体对应须有依据。

### 2. 新建 [han-208-admin-coverage-ledger.csv](computer:///workspace/han-208-admin-coverage-ledger.csv)

面向筛选与复核的台账，使用UTF-8 BOM、规范CSV引号转义，便于Windows Excel打开。一个文件采用两类记录，不额外拆出来源文件：

- `行政单位`：每个独立单位/沿革候选一行，使用 `A001` 起的审计ID；同名不同实体分别编号。
- `现有城邑`：每个稳定城池ID恰好一行，以 `C-城池ID` 编号，链接对应行政单位审计ID；未能判定的链接留空并填写原因。

固定列为：记录类型、审计ID、关联行政单位ID、州/司隶、单位名称、单位类别、异名、截面有效性、有效期及事件依据、城池ID、原始城名、原始州名、原始郡名、核定代表城邑、核定归属、地图关系、证据状态、判断理由、来源ID、原文定位、冲突及待核事项。

原始字段逐字保留代码中的文字；核定名称及说明使用简体中文。多来源ID以分号分隔并对应审计说明中的来源索引；不以字符串去重代替实体识别。

## 四、资料核查规则

- 原始纪传、诏令及编年事件用于判断设撤和事件顺序；地理志提供基础名目；CHGIS/TGAZ及可取得的学术研究用于沿革、身份和定位交叉核对。
- 先查全相关《郡国志》卷次，再逐项应用后续建置变化；书目页只能证明书目存在，不能代替书中结论。
- 全国完整性、关键沿革及影响补城建议的核心结论须由至少三个独立来源交叉支持；不足时明确标注单源、争议或待核，不写成确定结论。重复转载、不同版本同一原文或相互转引不算独立佐证。
- 对每个关键结论主动查找相反记载，区分统计时间差、政权重复设置、异名和后世追称。
- 搜索摘要只作线索，实际引用须读取正文并记录定位；资料不可得时保留缺口，不凭记忆补齐。
- 基础名录无法闭合时，明确说明全国分母尚未确认；不得给出全国覆盖率或“已包含所有州郡”的结论。

## 五、执行步骤

- [ ] **步骤1：冻结只读现状。** 记录开始时工作树状态和相关源文件校验值；提取40城稳定ID、原始名称/州/郡字段，复核城市数、州标签数和不同州郡组合数。辅助脚本与下载资料仅放临时目录，不写入项目。
- [ ] **步骤2：建立独立行政名录。** 从完整基础史料分州登记单位，再记录基础史料年代至目标截面的设撤、更名和转属；包括地图没有城池的州郡及特殊候选。每项链接原文来源，尚不能裁定者保留不确定性。
- [ ] **步骤3：校核40城。** 按稳定ID逐城验证代表城邑及归属，并反向查询每个行政单位是否已有城池代表；重点检查同名、重复代表和改名ID。将有争议的现有代码判断与已核实记录分开。
- [ ] **步骤4：形成缺项及补城候选。** 按既定分类记录每个单位，确认地图范围依据；仅对证据充足的缺项提出候选。候选按消除州级空缺、区域覆盖空缺和史料确定程度排序，排序属于实施建议而非历史事实。
- [ ] **步骤5：交付并完成一致性复核。** 生成上述两份文件，逐项核对来源、计数和关联关系，最后确认应用文件校验值及已有工作树改动未被更动；在回复中给出结论、局限及文件链接。

## 六、验证与完成标准

- 台账包含全部40个稳定城池ID且各出现一次，原始字段与代码一致；稳定ID不得按现代或历史名称重新命名。
- 每个行政单位身份唯一；重名、异名、分置/并置和同郡多城得到明确处理，没有按城池数量重复统计行政单位。
- 每项有效性及地图关系有原因和可追溯来源；单源或争议结论不包装为已核实。
- 报告各州计数能从台账复算；已确认、待核及排除单位分别列出，不把不确定项悄悄排除后宣布完整。
- 每个补城候选具有当时名称与归属依据；没有依据的缺项明确留待核查，不生成猜测坐标。
- CSV可按规范解析，编码及换行便于Windows读取；来源ID、关联审计ID全部有效。
- 结束时检查工作树差异及源文件校验值：除获准审计文件外不产生本轮项目改动。此轮无代码变更，不重跑构建以免重写现有 `dist`，也不把旧测试结果当作史实验证。

## 七、假设与后续边界

- “下一步”沿用此前建议的州郡覆盖审计，而不是新的玩法系统或直接扩图。
- 本轮目标是形成可复核的缺项依据，不预设全国行政单位总数，也不承诺所有历史疑点均可消除。
- 审计发现与实际地图扩充是两项工作。增加城池会影响七格落位、道路、州界示意和回归数量，须在审计结果确认后另行确定范围，不在本轮顺手修改。
