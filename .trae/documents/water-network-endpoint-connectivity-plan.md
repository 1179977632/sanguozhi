# 水网末端连通修复计划

## Context

前一轮只检查单条河道采样序列是否连续，没有检查河口、湖泊出口或最终目标水体。对 `createWorld(189)` 的水域格做六向连通分量核查发现：长江、珠江末端仍是河流格而未入海；湘水、沅水止于洞庭湖，但洞庭湖水域没有接入长江；鄱阳湖水系已接入长江。此前用户已确认黄河、淮水本轮保留待定，不以自动延伸或无依据长线强接海岸。

## Goal

为地图明确编码并验证长江、珠江入海和洞庭湖接长江这三处示意连接；保留湘水、沅水止于洞庭湖及鄱阳湖既有连接；让审计清楚报告黄河、淮水尚未完成的入海终端。

## 方案

沿用 `src/world.ts` 既有河流控制点、`densifyRiver`、`RIVER_PATHS`、河流栅格化和 `findExplicitConfluences`，用固定、可审阅的示意控制点表达有限连接，不新增最近水域搜索或无界延伸算法。给河流记录添加下游终端关系（入海、入湖、汇入河流或待定）；让 `auditConnectivity` 按关系验证最终地图格。洞庭湖出口作为独立的“洞庭湖出水道”路线，从湖内接入长江共享控制点，避免把湘水或沅水直接延长到长江。水网连通性测试只允许在河、湖、近海格上做六向 BFS，不使用可穿越陆地的行军寻路。

新增河段是策略地图示意，不表示已经考证出汉末精确河口、河道或洞庭湖历史出口。黄河、淮水不改控制点，审计中以待定终端显式呈现。

## 文件

- `src/world.ts`：河流终端类型和记录、有限示意控制点、最终水域终端审计。
- `tests/world.test.ts`：纯水域 BFS、连接端点断言及黄河/淮水待定状态回归。

## 实施步骤

1. **先补失败测试**：在 `tests/world.test.ts` 添加带函数级注释的纯水域 BFS 辅助函数。测试预期长江和珠江末格为近海；洞庭湖出水道以共享汇流点接长江；湘水、沅水仍以洞庭湖为终点；赣水仍以鄱阳湖为终点且水域可达长江；黄河、淮水在审计中明确待定。确认旧数据无法满足新增断言。
2. **表达河流终端契约**：在 `src/world.ts` 定义终端联合类型，并传递到生成后的 `RiverRoute`。为各条现有河道声明其已表示的下游关系：河、湖或明确共享的目标河流；黄河和淮水声明为待定入海；新建的洞庭湖出水道声明汇入长江。待定仅针对这两条河，不可让其他缺失连接静默通过。
3. **补固定的局部水系控制点**：长江由 `(121.5, 31.3)` 延至已核对为近海格的 `(122.1, 31.1)`；珠江由 `(113.5, 22.8)` 延至近海格 `(113.8, 22.5)`。在长江现有 `(112.19, 30.35)` 至 `(114.31, 30.59)` 的直线段中插入 `(113.25, 30.47)` 作为共享汇流点；增加洞庭湖出水道控制点 `(113.10, 29.70)`、`(113.25, 30.05)`、`(113.25, 30.47)`。已核对 seed 189 中首点落于洞庭湖、末点及两处海口落于各自目标水域；使用既有河道栅格流程，在最终地图上用测试验证全段连续和水域连通。不更改黄河、淮水控制点，不强行连通太湖、巢湖或其他未声明水体。
4. **扩充最终世界审计**：保留现有河道连续、共享汇流、山道检查；增加河道记录非空且每格最终仍是水域的检查；按声明验证海口末格为 `coast`、湖泊末格的 `terrain/landform` 命中指定湖泊、河流汇入目标为双方共享的水域格；将黄河、淮水待定作为明确、稳定的审计项。其他终端不匹配应报告失败，不能过滤或转成待定。
5. **运行定向回归与整体检查**：确认水域 BFS 只遍历 `river/lake/coast`；锁定洞庭湖出口及鄱阳湖至长江的水路可达，锁定湘水、沅水、赣水仍落入预期湖泊，锁定黄河和淮水为唯一待定河流。保留 40 城、显式支流汇流、山道与移动规则测试。实施后运行 `npm test`、`npm run build` 并审阅 `git diff`。

## 验收标准

- 长江、珠江河道终端实际落在 `coast`，且新增路线连续。
- 洞庭湖水域经独立出水道与长江接通；该接点是双方共享的显式汇流点。
- 湘水、沅水仍止于洞庭湖；赣水仍止于鄱阳湖，且鄱阳湖可经纯水域到达长江。
- 黄河、淮水控制点保持不变，且在审计结果中是唯一待定终端；不能把水域总连通分量数量作为验收条件。
- 所有测试和生产构建通过；既有城池数量、城域及城址测试不回归。
