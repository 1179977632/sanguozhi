# 建安十三年地图数据校准实施计划

> **执行要求：** 按任务逐项实施并运行定向测试；本计划获用户确认前不得修改源代码。

**目标：** 将地图河道和40座城邑数据校准为建安十三年（208）刘表病逝前的时间截面，并让数据表达的精度与证据相符。

**方案：** 保留现有六边格、经纬度投影、40个稳定城池ID、河道绘制和州界近邻示意。校核所有城邑州郡字段和河网连接；移除河道控制线之外无史料根据的程序随机摆动；以史料注记、数据回归和生成结果测试分别约束历史判断与程序行为。不引入GIS依赖、行政区多边形或新的地图系统。

**技术栈：** TypeScript、Vite、Node `tsx --test`、npm。

---

## 当前状态分析

- [world.ts](file:///workspace/src/world.ts#L208-L252) 定义12条河的经纬度控制点和视觉宽度，并按河名生成确定性曲线；曲线中的侧向摆动由程序生成，不来自地理资料。河流宽度是游戏绘制/格化参数，不是历史实测宽度。
- [world.ts](file:///workspace/src/world.ts#L276-L318) 定义40座城，`province`、`prefecture` 是自由文本；`prefecture` 现混有郡、尹和县级名称。`createWorld(189)` 中的189是生成种子，不是历史年份。
- 河流先于城邑落格；城心会在目标位置附近搜索可用格，因此河道修改可能移动或漏掉城池。共享控制点而非“看起来相交”决定明确汇流。
- [main.ts](file:///workspace/src/main.ts#L117-L120) 与 [main.ts](file:///workspace/src/main.ts#L442-L477) 以城心最近归属生成州级示意界线，并不生成郡界或历史疆界。详情和搜索读取 `prefecture`，见 [main.ts](file:///workspace/src/main.ts#L707-L755)。
- [world.test.ts](file:///workspace/tests/world.test.ts#L1-L49) 当前测试覆盖地图生成、城池完整性、道路和移动规则，没有锁定历史数据，也没有充分校验最终河道水域。
- 已查到适用于复核的来源：复旦CHGIS数据说明、复旦《东汉政区地理》书目页及TGAZ具体沿革条目；《后汉书·郡国志》作为基础郡县名录；《三国志》等纪传用于判断208年事件先后；《水经注》用于支流/汇流关系的晚期资料交叉核对。现有资料已提示襄阳郡和临江郡置于208年，但仅有年份不足以证明它们在刘表病逝前已置，不能直接写入本时间截面。

## 拟议变更

### 1. `/workspace/src/world.ts`：统一208截面并校准数据

- 在数据区明确时间口径：截至刘表病逝前，计入此前已发生且有证据的事件；若史料仅给出“208年”而不能判断先后，不提前套用该设置。
- 逐条复核40个城池记录的州、郡/国/尹级归属、地图点代表的城邑、控制方描述和坐标依据。保留所有ID；`province` 表示州/司隶级归属，`prefecture` 表示郡国/尹级归属，`name` 表示地图上的城邑。不得将县名继续放入 `prefecture`。至少复核濮阳（现填濮阳縣）和梓潼（现填梓潼縣）这类县级值，以及襄阳、沙羡、鱼复、龙编、秣陵等存在年代或后世定位风险的条目。只有查证支持才改值；证据不足则保留近似坐标并在描述中限定，不用增加小数位制造精度。
- 逐水系复核12条河：黄河、长江、汉水、淮水、湘水、赣水、珠江、岷江、沱江、嘉陵江、涪江、沅水。先校核河网连接，再按有据可查的走廊更新控制点；特别复核岷江/沱江入长江、涪江入嘉陵江、湘水/沅水经洞庭水域入长江、赣水经鄱阳水域通江的表示。删除沅水直接与江陵长江节点相接的错误拓扑；不声称恢复208年精确河槽、湖岸或水宽。
- 移除由河名播种的程序侧向噪声，河线按经核对的控制点折线稠密化。保留 `width` 作为游戏视觉尺度；不做未经证据支持的平滑偏移。不要仅为古名更改河名并导致整条河形变化。
- 在相关数据段落添加简短来源和精度注记，注明《水经注》是后世水系关系参考而非208年测绘资料；不增加单独来源文件或运行时数据字段。

### 2. `/workspace/tests/world.test.ts`：固定历史记录与河道生成结果

- 增加40个城池ID完整且唯一的断言，以及以稳定ID为键的历史回归断言。固定所有经查证后实际改动的 `province`、`prefecture`、`name`、关键坐标和时间敏感描述；测试期待值独立写出，不从生产数据自动派生。测试注释注明主要史料依据和存在的年代限制。
- 增加河道拓扑断言，明确检查经核验的长江汇流控制点及指定支流关系；不再要求沅水在江陵直接汇入长江。湖泊承接的河流要验证其水域连通，不误判成直接河流控制点汇流。
- 增加生成后河流水域覆盖与城池落位检查：40城仍全部生成、城域完整且不重叠；验证代表性河段最终落入河/湖/海水域；核对关键城址没有因拓宽河道被推到不合理的距离。测试采用固定世界种子，保留现有道路、舟船和通行测试。
- 若新增测试辅助函数，按项目用户约定添加函数级注释；不引入新的测试框架。

### 3. `/workspace/src/main.ts`：准确标注行政层级与示意界线

- 将图层入口与说明中的“州郡线”改为“州界（示意）”，明确当前按城邑归属近似生成，并非历史疆界；不增加郡界渲染。
- 将详情中归属标签写为“州 · 郡国级归属”（保留州与 `prefecture` 的现有拼接方式），避免把县名误示为郡级。搜索逻辑继续读取现有字段。

## 假设与决定

- 时间基准固定为“208年刘表病逝前”；采用事件先后证据，不以整个208年作为同一瞬间，也不将病逝、刘琮降曹后的变化倒灌。
- 史料证据等级：原始纪传和诏令用于事件/控制先后；《后汉书·郡国志》用于基础行政名目；CHGIS/TGAZ和《东汉政区地理》用于沿革与定位交叉核对；《水经注》只辅助辨析水系。多个来源互相转引时不视为独立证据。
- 若年代或位置无法核定，保留明确的近似/待考说明，而不是填入推测值。显示坐标与线宽不宣称具有考古或现代测绘精度。
- 本次不重构行政层级类型、不改变势力机制、不构建历史疆界、不增加交互功能或外部依赖。
- 不改城市稳定ID、河道字段结构及主地图交互。州郡仍是静态数据，州界仍为近邻示意。

## 实施与验证步骤

1. 先逐条核对40城和12河的目标字段、来源及适用年代，只把有证据支持的结论写入数据；对“208年置但先后不明”的建置保留时间限定。
2. 在 `world.test.ts` 先写固定数据与拓扑测试，再运行 `npm test` 确认新增断言能捕捉旧数据/旧拓扑问题。
3. 更新 `world.ts` 城邑和河网；保持河道线由控制点决定，生成后确认汇流、湖泊连接与河水格落位。
4. 更新 `main.ts` 标签和说明；核对详情、搜索及默认关闭的州界示意图层仍正常。
5. 在 PowerShell 项目终端运行 `npm test` 和 `npm run build`；预期所有测试通过，TypeScript 检查及Vite生产构建成功。
6. 以默认种子189检查完整40城，并用少量固定替代种子核对城心偏移；人工查看襄阳、江陵—洞庭、宜宾—江州—江阳及黄淮河段，检查河线穿城、湖河断开及无证据的曲折。地图只用于验证程序呈现，不作为史实证据。
