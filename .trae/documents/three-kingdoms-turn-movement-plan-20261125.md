# 三国游戏首个玩法切片：回合制行军

## Summary

在现有建安十三年战略地图上加入一个最小可玩的回合制行军闭环：**军队从成都出发 → 选择目的地并规划路线 → 派遣 → 结束回合逐段移动 → 抵达后显示结果**。地图仍作为现有底图和地形规则来源，不调整城池资料、历史地形、河流、山脉或地图版式；只叠加军队当前位置与游戏状态。

本切片不做战斗、城池易手、武将、经济、AI、胜负条件或存档。

## Current State Analysis

- `src/world.ts` 提供静态 `World`、40 座城市、`MovementOptions`、`movementCost` 和 A* `findPath`。寻路费用按进入的路径格累计，起点费用为 0。
- `src/main.ts` 的 `selectRouteWaypoint`、`refreshRoute`、`drawRoute` 已支持两点路线预览；`initializeControls` 负责 DOM 控件绑定，`updateSelection` 更新详情面板。
- 当前没有可变军队、回合状态或路线执行逻辑。`City.faction` 是地图数据中的静态势力标签，不应直接改写为玩法占领状态。
- `package.json` 的测试命令显式列出测试文件，新增模拟逻辑测试时需要将新测试文件加入命令。

## Proposed Changes

### 1. 新增 `src/game-state.ts`

建立纯 TypeScript 的最小模拟状态，与 Canvas/Phaser 渲染分离：

- 可序列化状态包含回合数和一支军队的当前位置、行军状态、目的地、路径、下一个待进入格索引及派遣时的 `MovementOptions` 快照。
- 初始回合为 1；军队初始位于 `chengdu` 城心，采用步卒、无舟船、无栈道。
- 每回合预算固定为 **6 点移动力**，作为首版原型参数集中定义。结束回合时按路径顺序累计实际地形移动费用；不允许超预算进入下一格，剩余行动点不结转。
- 派遣命令只接受当前位置到目的地之间存在有效路径的指令；行军途中不允许改令、重复派遣或更改该军队的装备。目的格可为任一可达地图格。
- 抵达即标记行军完成；不改变 `World` 或 `City.faction`，不模拟敌军、战斗或占领。
- 为新增的具名函数添加简体中文函数级注释。导出创建初始状态、派遣军队、结束回合所需的最小纯函数/API。

### 2. 扩展 `src/main.ts`

- 将模拟状态保存在 UI 状态之外，通过显式操作调用 `game-state.ts`，不把回合/行军规则写入 Phaser 场景回调。
- 复用当前路线规划控件：行军规划从军队当前位置自动起步，玩家选择目的地后查看预览，并通过“派遣军队”确认；派遣前仍可清除预览。
- 在行军面板加入回合数、军队位置/目的地、当前回合移动结果，以及“派遣军队”“结束回合”操作。行军途中禁用重复规划/派遣，抵达或待命时允许规划下一次行军。
- 结束回合调用纯模拟函数，更新剩余路线、位置和报告；使用现有 Canvas 叠加绘制军队当前位置，不更改地图瓦片或地形绘制逻辑。保持现有自由路线预览、选城、缩放、筛选与移动端抽屉可用。
- 所有新增具名函数添加简体中文函数级注释。

### 3. 调整 `src/style.css`

只为新增行军状态与回合控件补充必要样式，沿用现有地图面板的色彩、间距和按钮风格；不做整页改版。

### 4. 新增 `tests/game-state.test.ts` 并更新 `package.json`

用现有 `node:test`/`tsx` 测试模拟逻辑，且将新测试文件加入 `npm test` 命令。至少覆盖：初始状态、合法/非法派遣、路线中存在不可通行地形时不产生命令、单回合预算上限、超预算路径格留到后续回合、到达后停止移动、行军中重复下令被拒绝、原始世界及城市势力标签不被修改。

## Assumptions & Decisions

- “先做三国游戏下一步”按一个可运行的最小战术循环理解，不扩成完整策略系统。
- 为避免擅自补入未定的战斗与占领规则，目的地抵达只结束移动，不自动改变城池控制方。
- 为让回合推进可观察，首版使用单支成都出发的抽象军队和 6 点/回合预算；这两个参数只服务原型，不代表已确认的史实或最终平衡值。
- 继续使用现有 Canvas 2D 地图和 Phaser 宿主；不重写引擎、不引入依赖、不扩充/修订历史地图数据。
- 不实现改令、撤军、AI、补给、招募、战斗、经济、存档及胜负判定。
